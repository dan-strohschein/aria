# v0.3 Sprint 1 — Associated Types in Bounds

**Goal:** Support `T: Iter<Item=U>` and `T: Iter<Item=i64>` in generic bound syntax.

**User capability unlocked:** Constrain generic iterator/container parameters to hold specific element types, and propagate associated types to other generic parameters. Enables sum/fold/map patterns like `fn sum[I: Iter<Item=i64>](xs: I) -> i64`.

---

## Current state (as of v0.2)

**Already works:**
- `TraitDef.assoc_type_names` — traits can declare associated type names
- `ImplDef.assoc_type_names` + `assoc_type_values` — impls bind associated types to concrete types
- `Self::Assoc` and `Type::Assoc` resolution via type-alias lookup (`ConcreteType_AssocName`)
- Multi-bound generics: `T: Eq + Hash`

**Doesn't work:**
- Bound syntax `T: Iter<Item=U>` — no parser recognition
- Binding associated types to other generic params (`U`) during monomorphization
- Binding associated types to concrete types (`Item=i64`) during bound checking

**Current storage:** FnSig carries bounds as plain strings (e.g. `"Eq+Hash"`). `_parse_generic_str` splits by `,` and `:`; `_check_multi_bound` splits each by `+` and calls `treg_has_impl(type_name, trait_name)`.

---

## Scope

Support the two common forms:

```aria
// Form A: bind associated type to a concrete type
fn sum[I: Iter<Item=i64>](xs: I) -> i64 { ... }

// Form B: bind associated type to another generic param
fn first[I: Iter<Item=U>, U](xs: I) -> U { ... }
```

**Out of scope for this sprint** (defer to v0.3 later sprint):
- Nested associated types in bounds (`T: Collection<Inner: Iter<Item=U>>`)
- Multiple associated-type constraints on one bound (`T: Iter<Item=U, Error=E>`) — one at a time
- Associated types in struct/impl generic bounds (only fn-generic for now)

## Implementation Details

### 1. Bound string format extension

**Current format:** generic params stored in FnDecl.s2 as `"T:Eq+Hash,U:Display"`.

**Proposed format:** `"T:Iter<Item=U>+Clone,U:Display"`.

The `<Item=X>` fragment attaches to the preceding trait name. Reserved chars inside are `=` (assoc name/value separator). `,` and `+` still separate at the outer level but must NOT split inside `<>`.

### 2. Parser: accept `Trait<Item=X>` in bound position

Current parser for generic param lists (in `_parse_fn`, `_parse_struct_decl`, etc.) reads the bound as an identifier followed by optional `+` repetitions. Extend to recognize `<` after the trait name:

```
bound = IDENT ( "<" IDENT "=" type_ref ">" )? ( "+" bound )*
```

Store the raw text `Iter<Item=U>` in the bound position of the generic string. Don't split yet — defer to the checker.

**File:** `src/parser/parser.aria` — grep for how `_parse_fn` assembles its generic-params string (probably via `_skip_type`-style walks).

### 3. Checker: extend `_parse_generic_str` to respect `<>` nesting

When splitting by `,` outside a segment, track `<>` depth. Same when splitting by `:` inside a segment (for `T:Bound`). Same when splitting bound by `+`.

**Pseudocode addition:**
```
mut angle_depth := 0
while i < slen {
    c := s.charAt(i)
    if c == "<" { angle_depth = angle_depth + 1 }
    if c == ">" { angle_depth = angle_depth - 1 }
    if angle_depth == 0 && c == "," { // split here }
    ...
}
```

### 4. New helper: `_parse_single_bound`

Takes a string like `"Iter<Item=U>"` or `"Clone"` and returns:
- `trait_name`: `"Iter"` / `"Clone"`
- `assoc_name`: `"Item"` / `""`
- `assoc_binding`: `"U"` / `""`

Represented as `[str]` (Aria's data-as-strings pattern): `[trait_name, assoc_name, assoc_binding]`.

### 5. `_check_multi_bound` extension

When checking `T: Iter<Item=i64>`:
1. Split bound by `+` (respecting `<>` depth)
2. For each sub-bound: parse via `_parse_single_bound`
3. If `assoc_name != ""`:
   - `treg_has_impl(treg, type_name, trait_name)` — existing check
   - Look up the impl: `treg_find_impl(treg, trait_name, type_name)`
   - Find its `assoc_type_values[i]` where `assoc_type_names[i] == assoc_name`
   - Compare to `assoc_binding`

**Two cases:**
- `assoc_binding` is a concrete type (e.g. `"i64"`): error if impl's value doesn't match
- `assoc_binding` is another generic param (e.g. `"U"`): BIND it — see step 6

### 6. Generic-param binding during call checking

In `_check_generic_call`, when we determine concrete types for `T`, `U`, `V`:

Currently, generics are inferred from arg types. For `fn first[I: Iter<Item=U>, U](xs: I)`, the caller passes `xs: MyIter` — we infer `I = MyIter`. Then `U` needs to come from `MyIter`'s `Item` associated value.

**Algorithm:**
1. Infer bound generic params from args (existing).
2. For each generic param that has NO arg-derived type (e.g. `U` used only in return type): scan other bounds for a binding. If `T: Trait<Assoc=U>` and we know T, look up the assoc value and bind U to it.

**Implementation:** new helper `_derive_from_assoc_bound`:
```
fn _derive_from_assoc_bound(treg, bound_str, known_type, param_name) -> str
```
Returns the concrete type for `param_name` if the bound binds it; else "".

### 7. Monomorphization propagation

Once `U` is bound to the impl's assoc value, it enters the substitution table for body re-lowering. Existing `substitute_type` plumbing should handle the rest.

### 8. Tests

`testdata/programs/assoc_bound_test.aria`:
```aria
trait Iter {
    type Item
    fn next(self) -> Item
}

struct IntStream { n: i64 }

impl Iter for IntStream {
    type Item = i64
    fn next(self) -> i64 = self.n * 2
}

fn double_first[I: Iter<Item=i64>](xs: I) -> i64 = xs.next()

entry {
    s := IntStream{n: 5}
    assert double_first(s) == 10
    println("assoc_bound_test passed")
}
```

And a generic-binding version:
```aria
fn first[I: Iter<Item=U>, U](xs: I) -> U = xs.next()

entry {
    s := IntStream{n: 7}
    assert first(s) == 14
    println("generic_assoc_test passed")
}
```

## Risks

| Risk | Mitigation |
|------|------------|
| Parser ambiguity: `<` as bound-assoc vs. generic-arg | Only allow `<` after trait name inside a bound position, not in type-ref position |
| `+` splitting inside `<>` — existing `_check_multi_bound` doesn't track depth | Add depth tracking (item 3) |
| Associated-type value in impl is itself generic | Out of scope — defer |
| Bound refers to generic param `U` declared AFTER current bound | Parse all generic names first (2-pass), then resolve bindings |
